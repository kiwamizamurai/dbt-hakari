dbt × BigQuery on-demand

Weigh your views. Shave your bill. 秤にかけて、請求を削る。

dbt-hakari checks BigQuery's billing formula against your real bill, then finds exactly which dbt views are worth turning into tables, with integer programming instead of guesswork. BigQuery の請求の式を、実際の請求で確かめ、どの dbt の view を table にすべきかを、勘ではなく整数計画法で厳密に求めます。

The problem問題

A view read twice is paid for twice.2 回読まれる view は、2 回払う。

BigQuery bills at least 10 MiB for every table a query touches. A dbt view is expanded to its base tables each time it is read, so every test and every downstream model pays that minimum again. BigQuery は、クエリが触れるテーブル 1 つにつき、最低 10 MiB を課金します。dbt の view は、読まれるたびに元のテーブルへ展開されるので、テストや下流のモデルのたびに、その最小額を払い直します。

billed = max( bytes, 10 MiB × tables, 10 MiB ) Materialize a view over T tables read by n readers when n·T > T + n.T 個のテーブルを n 個が読む view は、n·T > T + n のとき、table にすると得です。
How it works仕組み

Measure. Verify. Optimize.測る。確かめる。選ぶ。

It only recommends after it has proven, on your own project, that its cost model matches your bill.あなた自身のプロジェクトで、コストの式が実際の請求と合うと確かめてから、はじめて提案します。

collect

Dry-runs every model and test (free) and reads the last 14 days of job history with one capped SELECT.全モデルとテストを dry-run し（無料）、直近 14 日の履歴を、上限つきの SELECT 1 回で読みます。

hakari collect --project my-project \ --location asia-northeast2

verify

Compares the formula with what you were really billed. If it does not match, it refuses to go on.式と、実際に請求された額を比べます。合わなければ、そこで先に進みません。

hakari verify --format json
PASSWARNFAIL → exit 4

optimize

Solves for K = 0, 1, 2, … views exactly (MILP, HiGHS) and shows how far greedy selection falls behind.K = 0, 1, 2, … 個の view の最適な選び方を、厳密に（MILP、HiGHS）解き、貪欲法との差も示します。

hakari optimize --max-k 8 \ --compare-greedy
Result結果

Exact beats greedy, and you see by how much.貪欲法より確実に良く、その差も見える。

The best set of K views is not nested: the best 4 do not contain the best 3. Greedy selection drifts away from the optimum as K grows.K 個の最適な選び方は入れ子になりません。K を増やすと、貪欲法は最適解から離れていきます。

Built to be trusted信頼のために

Careful by default.慎重さが、既定。

∑Exact optimization厳密な最適化

A mixed-integer program solved by HiGHS, cross-checked against brute force on random DAGs.HiGHS で解く混合整数計画。ランダムな DAG で、全探索との一致を確かめています。

✓Trust gate信頼ゲート

Checks table counts against dry-runs and the formula against your real bill before recommending anything.提案の前に、テーブル数を dry-run と、式を実際の請求と照合します。

⊘Read-only and cheap読み取り専用で安価

Only dry-runs and one capped INFORMATION_SCHEMA SELECT. Anything else raises an error.dry-run と、上限つきの INFORMATION_SCHEMA への SELECT 1 回だけ。それ以外は、エラーにします。

⌘CI-readyCI で使える

--format json|markdown, results on stdout, messages on stderr, stable exit codes.--format json|markdown。結果は stdout、メッセージは stderr、終了コードも固定です。

⚑Pin what must stay a viewview のまま残すものを固定

A .hakari-ignore file with a reason per line, shown in the plan.1 行ごとに理由を書ける .hakari-ignore。プランにも表示されます。

⟡Typed and validated型つきで検証済み

Pydantic models and constrained types: a bad config value is reported with its name.pydantic のモデルと制約つきの型。設定の誤りは、項目名つきで報告されます。

Install導入

Not on PyPI. Just a wheel.PyPI なしで、wheel 1 つ。

Install the wheel from the latest GitHub release with the tool you already use. Python 3.10+.普段使っているツールで、最新の GitHub Release の wheel を入れます。Python 3.10 以上。

uv tool install https://github.com/kiwamizamurai/dbt-hakari/releases/download/v0.1.0/dbt_hakari-0.1.0-py3-none-any.whl
pipx install https://github.com/kiwamizamurai/dbt-hakari/releases/download/v0.1.0/dbt_hakari-0.1.0-py3-none-any.whl
pip install https://github.com/kiwamizamurai/dbt-hakari/releases/download/v0.1.0/dbt_hakari-0.1.0-py3-none-any.whl
uvx --from git+https://github.com/kiwamizamurai/dbt-hakari hakari --help

Then: hakari collect, hakari verify, hakari optimize. You need a target/manifest.json from dbt compile.そのあと、hakari collect、hakari verify、hakari optimize の順に実行します。dbt compile で作った target/manifest.json が必要です。

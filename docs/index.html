dbt × BigQuery on-demand

Weigh your models. Shave your bill. 秤にかけて、請求を削る。

dbt-hakari checks BigQuery's billing formula against your real bill, then finds exactly which dbt models are worth turning into tables, or back into views, with integer programming instead of guesswork. And it tells you when nothing is worth changing. BigQuery の請求の式を、実際の請求で確かめ、どの dbt のモデルを table に（または view に戻す）べきかを、勘ではなく整数計画法で厳密に求めます。変更する価値がないときは、そう言います。

The problem問題

A view read twice is paid for twice.2 回読まれる view は、2 回払う。

BigQuery bills at least 10 MiB for every table a query touches. A dbt view is expanded to its base tables each time it is read, so every test and every downstream model pays that minimum again. BigQuery は、クエリが触れるテーブル 1 つにつき、最低 10 MiB を課金します。dbt の view は、読まれるたびに元のテーブルへ展開されるので、テストや下流のモデルのたびに、その最小額を払い直します。

billed = max( bytes, 10 MiB × tables, 10 MiB ) Materialize a view over T tables read by n readers when n·T > T + n.T 個のテーブルを n 個が読む view は、n·T > T + n のとき、table にすると得です。
How it works仕組み

Measure. Verify. Optimize.測る。確かめる。選ぶ。

It only recommends after it has proven, on your own project, that its cost model matches your bill.あなた自身のプロジェクトで、コストの式が実際の請求と合うと確かめてから、はじめて提案します。

collect

Dry-runs every model and test (free) and reads the last 14 days of job history with one capped SELECT.全モデルとテストを dry-run し（無料）、直近 14 日の履歴を、上限つきの SELECT 1 回で読みます。

hakari collect --project my-project \ --location US

verify

Compares the formula with what you were really billed. If it does not match, it refuses to go on.式と、実際に請求された額を比べます。合わなければ、そこで先に進みません。

hakari verify --format json
PASSWARNFAIL → exit 4

optimize

Solves exactly (MILP, HiGHS) for at most K = 0, 1, 2, … changes, view to table or table to view, and says what the result is worth in money.変更が最大 K = 0, 1, 2, … 個のときの最適な選び方を、view → table も table → view も、厳密に（MILP、HiGHS）解き、お金でいくらの価値かも示します。

hakari optimize --max-k 8 \ --direction both

Two more commands answer the questions people ask next: hakari report shows where the bill goes, and hakari explain <model> shows who reads a model, what each reader pays, and why it is, or is not, worth changing. 次に聞かれる 2 つの問いには、2 つのコマンドが答えます。hakari report は、請求がどこに行っているかを、hakari explain <モデル> は、誰がそのモデルを読み、それぞれがいくら払うか、変更に値するかの理由を示します。

Built to be trusted信頼のために

Careful by default.慎重さが、既定。

∑Exact optimization厳密な最適化

A mixed-integer program solved by HiGHS, cross-checked against brute force on thousands of random projects.HiGHS で解く混合整数計画。何千もの乱数のプロジェクトで、全探索との一致を確かめています。

✓Trust gate信頼ゲート

Checks the formula against your real bill before recommending anything, and points out models changed during the history window.提案の前に、式を実際の請求と照合します。履歴の期間中に変更されたモデルも、指摘します。

⇄Both directions, with guards両方向と、安全ガード

A table becomes a view only when everyone who reads it is known: dbt, and the apps and BI services seen in the job history.table を view にするのは、読む人が全員分かっているときだけ。dbt と、履歴に見えるアプリや BI サービスまで見ます。

¥Says what it is worth価値を、お金で言う

The bill per month, the saving, the free tier, and a plain "nothing to change" when that is true. Laptop runs and ad-hoc analysis are not counted as the schedule.月の請求、節約額、無料枠。変更の価値がなければ、そう言います。ローカルの実行やアドホックな分析は、スケジュールとして数えません。

⊘Read-only and cheap読み取り専用で安価

Only dry-runs and one capped INFORMATION_SCHEMA SELECT. Anything else raises an error.dry-run と、上限つきの INFORMATION_SCHEMA への SELECT 1 回だけ。それ以外は、エラーにします。

⌘CI-readyCI で使える

--format json|markdown, stable exit codes, and a .hakari-ignore to keep models as they are.--format json|markdown、固定の終了コード、そのままにするモデルを固定する .hakari-ignore。

Install導入

Not on PyPI. Just a wheel.PyPI なしで、wheel 1 つ。

Install the wheel from the latest GitHub release with the tool you already use. Python 3.10+.普段使っているツールで、最新の GitHub Release の wheel を入れます。Python 3.10 以上。

uv tool install https://github.com/kiwamizamurai/dbt-hakari/releases/download/v0.2.0/dbt_hakari-0.2.0-py3-none-any.whl
pipx install https://github.com/kiwamizamurai/dbt-hakari/releases/download/v0.2.0/dbt_hakari-0.2.0-py3-none-any.whl
pip install https://github.com/kiwamizamurai/dbt-hakari/releases/download/v0.2.0/dbt_hakari-0.2.0-py3-none-any.whl
uvx --from git+https://github.com/kiwamizamurai/dbt-hakari hakari --help

Then: hakari collect, hakari verify, hakari optimize (and hakari users to see who ran what). You need a target/manifest.json from dbt compile.そのあと、hakari collect、hakari verify、hakari optimize の順に実行します。dbt compile で作った target/manifest.json が必要です。
